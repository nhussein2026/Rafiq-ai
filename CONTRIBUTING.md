# Contributing to Rafiq

Thanks for helping! Rafiq takes part in **Hacktoberfest 2026**. Quality matters more than quantity: spam or low-effort PRs will be labelled `spam` / `invalid`.

## Getting started

1. Find an issue labelled `hacktoberfest` or `good first issue` and comment to get it assigned.
2. Fork the repo and create a branch: `git checkout -b feat/short-description`.
3. Set up: `pip install -e ".[dev]"` (see README).
4. Make your change and add tests where possible.
5. Run `ruff check .` and `pytest` — both must pass.
6. Open a PR using the template and link the issue (`Closes #123`).

## ⚠️ Rules for religious content (read carefully)

Rafiq's core promise is that it never fabricates Islamic evidence. So:

- **Never** add Quran text, hadith, gradings, fatwas or scholar quotes generated by an AI tool or typed from memory.
- Quran text in `data/approved_sources.json` must be copied **verbatim** from [Tanzil](https://tanzil.net), with the verse ID and source URL.
- New records start with `"review_status": "pending"`. Only maintainers with a qualified reviewer can mark them `approved`.
- Do **not** scrape or bulk-copy Islamweb, Sunnah.com, Dorar or Quran Foundation content. Link only, and respect their terms.
- Hadith support stays disabled until rights and reviewer approval are in place (`config/policy.yaml`).

## Rules for safety code

Changes to `src/rafiq/safety.py` or `skills/01_safety.md` need a maintainer review. Never add unverified hotline numbers, and never add content that describes self-harm methods, including in tests.

## Changing skills

Skills in `skills/` are product rules. Open an issue to discuss behaviour changes before sending a PR, and add or update a scenario in `tests/scenarios/TEST_CASES.md`.

## Code style

- Python 3.10+, formatted and linted with `ruff`.
- Keep functions small; match the style of surrounding code.
- Never commit API keys or `.env` files.

## Commit messages

Use short, imperative messages, e.g. `fix: detect Egyptian-dialect crisis phrases`.
